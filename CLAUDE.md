# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Run the server on http://localhost:8080 (Swagger UI at `/docs`):

```bash
docker compose up --build          # also starts postgres + redis (not used by the code yet)
```

Without Docker (PowerShell; the package lives under `src/`, so `PYTHONPATH` is required):

```powershell
pip install -r requirements.txt
$env:PYTHONPATH = "src"; uvicorn openapi_server.main:app --host 0.0.0.0 --port 8080
```

Tests (pytest is not in requirements.txt; install it separately with `pip install pytest`). `pyproject.toml` already puts `src/` on the path, so no `PYTHONPATH` is needed:

```powershell
python -m pytest                                              # whole suite, <1s
python -m pytest tests/test_orders_api.py::test_confirm_order # single test
python -m pytest -k expired                                   # by name
```

The tests are hand-written (`tests/*` is in `.openapi-generator-ignore`) and drive the app through `TestClient`. The autouse `reset_state` fixture in `conftest.py` restores the demo data and clears users and orders around every test. It restores state **in place**, because `orders_impl` imports `SOLD`/`SHOWINGS` by name, and it lowers `PBKDF2_ITERATIONS` to keep hashing fast. The `alice`/`bob`/`login` fixtures give auth headers, and `seat_status` reads the public seat map. Hold expiry is tested by setting `orders_impl.HOLD_MINUTES` to 0 instead of mocking the clock.

Lint: `flake8` (max line length 88, config in `.flake8`); black/isort settings live in `pyproject.toml`.

Docker installs dependencies from `setup.cfg` (`pip install .`), not from `requirements.txt`. Add new dependencies to **both** files.

## Architecture

FastAPI server generated by OpenAPI Generator (`python-fastapi`) from `openapi.yaml`, plus hand-written code on top.

**Generated layer vs. implementation layer.** `apis/*_api.py` define the routes and delegate to `Base*Api.subclasses[0]()`. A `Base*Api` class registers every subclass through `__init_subclass__`, and each `*_api.py` imports every module in `openapi_server/impl/` with `pkgutil`. To implement endpoints, subclass the base class in a module under `impl/` (see `impl/showings_impl.py`, `impl/orders_impl.py`). If there is no subclass, the route returns `500 Not implemented`.

**Hand-edited generated files.** `main.py`, `security_api.py`, `apis/orders_api.py` and `apis/orders_api_base.py` were changed by hand and are listed in `.openapi-generator-ignore` so regeneration won't overwrite them. The orders router passes `token_bearerAuth.sub` (the username) as an extra `username` argument to every impl method, and it sets the spec's status codes (201 for create, 204 for delete). If you regenerate from `openapi.yaml`, keep these edits and apply the same pattern to any new authenticated router.

**Auth.** `auth.py` is hand-written and not part of `openapi.yaml`: it provides `POST /register` and `POST /login` (JSON `{username, password}`), PBKDF2-SHA256 password hashes, and HS256 JWTs signed with `JWT_SECRET` that expire after `JWT_EXPIRE_MINUTES`. `security_api.get_token_bearerAuth` validates the token and returns `TokenModel(sub=username)`.

**Errors.** Raise `errors.ApiError(status, code, message)` from impl code. `main.py` calls `register_error_handlers`, which turns it into the spec's `Error` body, `{"code", "message"}`. Pydantic validation failures still return FastAPI's default 422 `{"detail": [...]}`.

**State is in memory only.** Every piece of state is a module-level dict, and restarting clears everything. Postgres and Redis are only declared in the compose file.

| State | Lives in |
|---|---|
| Users | `auth.USERS` |
| Orders (each has an owner) | `impl/orders_impl.ORDERS` |
| Showings, seat grids, sold seats and held seats | `impl/showings_impl`: `SHOWINGS`, `SEAT_LAYOUTS`, `SOLD`, `HELD` (every showing needs a `SEAT_LAYOUTS` entry) |

**Order and seat-hold lifecycle** (`impl/orders_impl.py`):
- **Create:** an order starts as `PENDING` and holds its seats until `holdExpiresAt`, which is `ORDER_HOLD_MINUTES` after creation (default 10).
- **Expiry is lazy; there is no background job.**
  - `HELD[showingId][seat]` stores `(orderId, expiresAt)`. `showings_impl.active_holds()` drops expired entries whenever holds are read.
  - `orders_impl._load()` switches an overdue `PENDING` order to `EXPIRED`.
  - Releasing holds only removes entries owned by that order. This matters because an expired seat may already be held by someone else.
- **Demo holds:** `(None, None)` entries are permanent demo holds and always count as taken.
- **Confirm:** requires `passengerName`, `contactEmail` and `paymentToken`. The payment gateway is simulated: tokens must start with `tok_`, and `tok_chargeDeclined` returns 402. Confirming moves the seats from `HELD` to `SOLD`.
- **Cancel:** `DELETE` cancels a `PENDING` order, or refunds a `CONFIRMED` one if the showing hasn't started.
- **Ownership:** another user's order returns 404.

`openapi.yaml` declares the server URL as `https://api.example.com/v1`, but the app does not mount a `/v1` prefix. Routes are served at the root, for example `/showings` and `/orders`.
